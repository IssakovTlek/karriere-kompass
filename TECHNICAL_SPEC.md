# Техническое задание: Career Agent Germany

## 1. Назначение

Веб-сервис помогает кандидату находить подходящие вакансии в Германии, оценивать их по резюме и готовить персонализированные черновики откликов. Сервис предназначен для Нуржана Алижана, incoming-студента International Business Administration в SRH University Heidelberg.

Сервис **не отправляет отклики автоматически** и не создаёт аккаунты на сайтах работодателей. Любая отправка остаётся явным действием пользователя.

## 2. Целевая аудитория и роли

### Кандидат

- просматривает найденные вакансии;
- меняет предпочтения, резюме и доступность;
- одобряет, редактирует и скачивает черновики откликов;
- сохраняет статус своего отклика.

### Администратор (MVP: тот же пользователь)

- подключает и отключает источники вакансий;
- видит ошибки синхронизации;
- управляет периодичностью поиска.

## 3. Профиль кандидата по умолчанию

| Поле | Значение |
| --- | --- |
| Локация | Heidelberg, Germany |
| Радиус | 40 км |
| Города-приоритеты | Heidelberg, Mannheim; прочие города в радиусе |
| Формат | Только офис или гибрид |
| Исключения | Полностью удалённые и online-вакансии |
| Типы вакансий | Internship/Praktikum, Working Student/Werkstudent, Volunteer/Ehrenamt |
| Направления | Business Development, Marketing, Sales, Customer Acquisition, Digital Content, AI |
| Образование | B.A. International Business Administration, SRH University, старт октябрь 2026 |
| Языки | English, German, Russian, Kazakh |

Профиль должен редактироваться в интерфейсе. Сервис не должен утверждать в отклике дату старта, наличие разрешения на работу, уровень языка или навыки, которых пользователь явно не подтвердил.

## 4. Функциональные требования

### 4.1. Онбординг и настройки

1. Пользователь создаёт аккаунт через email и пароль либо Google.
2. Пользователь загружает PDF-резюме или вставляет данные вручную.
3. Система извлекает текст из PDF и показывает его для проверки перед сохранением.
4. Пользователь задаёт: доступную дату старта, часы в неделю, предпочитаемые языки откликов, радиус, типы работы и список исключений.
5. По умолчанию включены Heidelberg, Mannheim и радиус 40 км.

### 4.2. Сбор вакансий

1. Планировщик запускает поиск один раз в сутки; пользователь может запустить поиск вручную.
2. Первичные источники MVP: Google Jobs через SerpApi. Архитектура должна позволять добавить Bundesagentur für Arbeit, LinkedIn, Indeed и карьерные страницы компаний отдельными адаптерами.
3. Для каждого поиска формируются запросы на немецком и английском: Werkstudent/Working Student, Praktikum/Internship, Ehrenamt/Volunteer с направлениями из профиля.
4. Система нормализует название, компанию, город, описание, дату публикации, URL и источник.
5. Система объединяет дубликаты по URL либо нормализованной паре «компания + название + город».
6. Вакансия принимается в основную ленту, если одновременно:
   - её город или координаты находятся в радиусе пользователя;
   - тип соответствует выбранным типам;
   - формат явно office/on-site или hybrid;
   - она не помечена как полностью remote/online.
7. Если адрес не удалось проверить, вакансия отображается отдельно с пометкой «проверьте локацию», но не попадает в автоподборку.

### 4.3. AI-оценка

1. Для каждой прошедшей фильтры вакансии AI получает только профиль кандидата и текст вакансии.
2. AI возвращает строго структурированный результат:
   - оценка соответствия от 0 до 100;
   - до четырёх причин соответствия;
   - пробелы или вопросы для кандидата;
   - рекомендуемый язык отклика;
   - краткое объяснение, почему формат и локация прошли фильтр.
3. Вакансии с оценкой 70+ попадают в «Рекомендовано»; порог пользователь может изменить.
4. В интерфейсе должна быть пометка, что оценка AI носит рекомендательный характер.

### 4.4. Черновики откликов

1. По кнопке «Подготовить отклик» система создаёт cover letter на немецком или английском.
2. Письмо содержит тему, обращение, 2-3 коротких абзаца и подпись.
3. Текст должен опираться только на подтверждённые данные профиля и резюме.
4. Перед скачиванием доступны редактирование, копирование и экспорт в PDF/DOCX на следующем этапе; для MVP достаточно редактора и копирования текста.
5. На странице отображается ссылка на оригинальную вакансию и предупреждение: «Проверьте требования и данные до отправки».

### 4.5. Трекер откликов

Статусы: `сохранено`, `черновик готов`, `отправлено вручную`, `интервью`, `отказ`, `оффер`, `архив`.

Пользователь вручную меняет статус, добавляет заметки и дату следующего действия. Дашборд показывает количество вакансий, подготовленных черновиков и откликов по статусам.

## 5. Страницы MVP

| Страница | Содержимое |
| --- | --- |
| Вход / регистрация | Аутентификация, восстановление пароля |
| Онбординг | Резюме, профиль, доступность, география и предпочтения |
| Дашборд | Новые вакансии, рекомендованные роли, счётчики трекера |
| Вакансии | Карточки, фильтры, поиск, сортировка по оценке/дате/расстоянию |
| Карточка вакансии | Описание, источник, соответствие, причины, пробелы, действия |
| Черновик отклика | Редактор письма, выбор языка, копирование, отметка «отправлено вручную» |
| Трекер | Канбан или таблица со статусами и заметками |
| Настройки | Профиль, резюме, ключи источников, расписание, удаление данных |

## 6. Нефункциональные требования

- Язык интерфейса MVP: русский; вакансии и письма сохраняются в исходном языке.
- Адаптивность: desktop от 1280 px и mobile от 360 px.
- Время загрузки ленты из уже сохранённых данных: до 2 секунд при 1 000 вакансиях на пользователя.
- История каждого запуска поиска, включая ошибки источника, хранится 90 дней.
- API-ключи источников и OpenAI шифруются на сервере; никогда не передаются в браузер и не попадают в логи.
- Резюме, контакты и письма считаются персональными данными. Нужны экспорт данных и полное удаление аккаунта.
- Логи не должны содержать email, телефон, полный текст резюме или токены.

## 7. Рекомендуемая архитектура

### Frontend

- Next.js + TypeScript;
- Tailwind CSS и компонентная библиотека;
- server-side страницы для защищённых данных;
- формы с валидацией Zod.

### Backend

- Next.js Route Handlers или отдельный FastAPI-сервис;
- PostgreSQL + Prisma/SQLAlchemy;
- очередь задач: Redis + BullMQ/Celery;
- ежедневные синхронизации в worker-процессе;
- OpenAI Responses API для извлечения профиля, оценки и черновиков;
- S3-совместимое хранилище для исходных PDF.

### Внешние интеграции

- SerpApi (Google Jobs) в MVP;
- геокодер для проверки расстояния: OpenStreetMap Nominatim с соблюдением лимитов либо коммерческий сервис;
- email-провайдер только для сервисных уведомлений, без отправки заявок работодателям.

## 10. Ограничения и правила безопасности

1. Запрещена автоматическая отправка заявок, ввод паролей на job board и обход CAPTCHA.
2. Сбор данных выполняется только через разрешённые API или публично доступные интеграции с соблюдением их условий.
3. Ссылка на источник и дата обнаружения обязательны для каждой вакансии.
4. Ответы AI должны быть проверяемыми: рядом с выводом показываются фрагменты вакансии, на которых основана рекомендация.
5. Перед созданием письма показывается, какие данные кандидата будут переданы AI; пользователь может отключить генерацию.

## 11. Критерии приёмки MVP

1. Пользователь может создать профиль, загрузить PDF и исправить извлечённые данные.
2. После запуска поиска сервис показывает вакансии из подключённого источника и удаляет дубликаты.
3. В ленте нет вакансий с признаком fully remote, remote only, online only или 100% Homeoffice.
4. В рекомендации попадают только типы internship, working student или volunteer и только локации в заданном радиусе; сомнительные локации помечены отдельно.
5. Для каждой рекомендованной вакансии видны оценка, причины, пробелы, ссылка на источник и черновик отклика.
6. Пользователь может отредактировать черновик и вручную поставить статус «отправлено».
7. API-ключи и персональные данные не отображаются в интерфейсе, сетевых ответах и логах.

## 12. Этапы реализации

1. **Основа:** аутентификация, профиль, база данных, загрузка PDF, дизайн-система.
2. **Поиск:** адаптер SerpApi, нормализация, география, дедупликация, ежедневная очередь.
3. **Подбор:** AI-оценка, фильтры, карточка вакансии, сохранение рекомендаций.
4. **Отклики:** редактор черновиков, трекер, экспорт и контроль пользователя.
5. **Качество:** тесты фильтров, мониторинг синхронизаций, аудит безопасности и privacy review.
